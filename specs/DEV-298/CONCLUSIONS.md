# DEV-298 Conclusions

## Phase A grill, round 1

1. **Q1 — scope:** Deliver the six named Core port interfaces and the contract types required by their signatures. Adapters, DI wiring, and rewrites of legacy Worker, Web, or controller code are outside this ticket. Basis: DEV-298 Overview and Scope & Technical Design item 1; constitution I, lines 111–120; charter §2.3 item 6. No owner checkbox.
2. **Q2 — contract fields:** The ticket fixes `EnrichmentRequested(MovieId MovieId, int Attempt)` and the three `MetadataLookupResult` cases, but does not specify the other field sets. Define `PagedResult<T>(ImmutableArray<T> Items, int TotalCount)`; `MovieSummary(MovieId Id, string Title)`; `MovieDetails(MovieId Id, string Title, LibraryPath Path, MediaFormat Format, MovieMetadata? Metadata)`; `MetadataLookup(string Title, ReleaseYear? ReleaseYear)`; and `ScannedMovie(LibraryPath Path, string Title, MediaFormat Format)`. Use the ticket's exact `EnrichmentRequested` fields. These are the smallest fields that identify, display, locate, or search the movie for the named operations; avoid transport, persistence, or adapter fields. Basis: DEV-298 Scope & Technical Design item 1; existing `Movie`, `MovieMetadata`, and `MovieQuery` Core domain types; constitution I, lines 111–114; engineering practice. No owner checkbox.
3. **Q3 — placement:** Put the six ports and their port-specific contract types in `Core/Ports/`; retain the already delivered `MovieQuery` in `Core/Library/` and reference it from `IMovieCatalog`. `Ports` is a shared location, not a feature folder, so this does not create a feature-to-feature reference. `ArchitectureTests.cs:81–109` checks feature references to Ports, Domain, and Pipeline; it does not currently ban Ports referencing Library. Basis: DEV-298 Scope item 1; constitution I, lines 112–120; architecture test lines 81–109. No owner checkbox.
4. **Q4 — lookup result:** Use an abstract record with private constructor and sealed nested `Found(MovieMetadata)`, `NotFound`, and `Failed(EnrichmentFailureCategory)` records. Add no package or SmartEnum conversion. Basis: DEV-298 Scope item 1 names precisely these cases; constitution I, line 105 limits Core dependencies; engineering practice for a closed union. No owner checkbox.
5. **Q5 — time:** None of the six specified port methods takes or returns a timestamp or has a ticket-defined time policy. Add no TimeProvider parameter to their fixed signatures. Inject `TimeProvider` into future time-sensitive adapters or handlers where timestamps are created; if a future method has a time-dependent contract, define that at its ticket. Basis: DEV-298 Scope items 1–2; constitution VII, lines 256–257. No owner checkbox.
6. **Q6 — sync:** Keep `ScannedMovie Scan(LibraryPath folder)` and `void Launch(LibraryPath file, MediaFormat format)` synchronous with no CancellationToken. Basis: DEV-298 Scope item 1 gives these exact signatures. Async or cancellation would change ticket text and needs a structural owner checkbox before adoption.
7. **Q7 — LocalPlay:** Define only `IMediaPlayerLauncher`; defer `DisabledMediaPlayerLauncher`, `FeatureDisabledException`, DI gating, and Process.Start behavior to the playback adapter work. Basis: DEV-298 Scope item 1; constitution VII, lines 253–255; charter §2.3 item 5. No owner checkbox.
8. **Q8 — enforcement:** Extend `LamuFlix.ArchitectureTests` to enforce that Core's port interfaces are only constitution-listed names and that Core has no concrete infrastructure dependencies. Preserve its existing feature-reference rule. The current test at `ArchitectureTests.cs:81–109` does not enforce the port whitelist. Basis: constitution I, lines 105–120; DEV-298 acceptance criteria. No owner checkbox.
9. **Q9 — other ports:** Exclude `IRecommendationCandidateSource` and `IPlaybackHistory` from DEV-298 because its Scope names six ports. Check existing open tickets for their delivery, then use a DEV-282 follow-up only for an uncovered port; do not duplicate an existing ticket. Basis: DEV-298 Scope item 1; constitution I, lines 115–119; charter follow-up-ticket rule. No owner checkbox.
10. **Q10 — tests and mutation:** Test the architecture rule and meaningful invariants for any contract type that implements them. Cover each `MetadataLookupResult` case if the union exposes matching behavior. Interface-only declarations need no mirror tests. A zero-tested-mutant mutation invocation has no score: report N/A without calling it PASS, and follow the applicable gate's actual result. Basis: constitution I, line 120; project non-negotiables on surviving mutants and gate exits; engineering practice. No owner checkbox.
11. **Q11 — claim contract:** Document `TryClaimForEnrichmentAsync` as an atomic claim attempt: true only when the movie exists and this call newly claims it; false when absent or already claimed. Leave storage mechanics to the adapter. Basis: DEV-298 Scope item 1 names a `TryClaim` boolean method; engineering practice for race-safe claims. No owner checkbox.
12. **Q12 — ADR:** No ADR is needed for these six already constitution-listed ports; create one only if a new port beyond that list is proposed. Basis: DEV-298 Scope item 1; constitution I, lines 115–119. No owner checkbox.
