## Grill answers

1. **Q1 — Persistence and identity.** Use one ticket-owned PostgreSQL table. Its unique key is movie identity plus the actual published path relative to the movie folder, including `Subs\` when present. Record the selected candidate's canonical provider ID, release name, language, hash-match evidence and match percent, plus download UTC time from injected `TimeProvider`. Persist after successful publication. Q7 supersedes the original insert-only assumption. Q1 basis is Wanted 1/4, the persistence open point and the deleted-file acceptance criterion.
2. **Q2 — Failed metadata write.** Keep successfully published bytes and use the existing successful download response with the filename-derived label and explicit null provider/release on a failed metadata write. Log the failure at Error through the existing logging path with movie ID and relative path. Cancellation or an ambiguous write does not trigger deletion, rollback or duplicate publication. The next list reflects the committed row if present. Q9 specifies the same-key case.
3. **Q3 — Public contract.** Add nullable string `provider` and `releaseName` with explicit nulls when unknown to the existing track DTO on both list and download. `provider` is the canonical DEV-551 provider ID verbatim. Preserve existing `id`, `label`, `language`, `isDefault`, routes and status codes. Core ranks, the selector groups and preserves each language's incoming order, and ranking evidence stays internal. Both response mappings and generated artifacts are required by the DTO and contract chain.
4. **Q4 — Ranking and display.** Partition by language in first discovery appearance order. Within a language, place recorded tracks first and sort by hash match first, then known match percent descending, then download UTC descending. Place a missing score after known scores at the same hash rank. Preserve discovery order for exact ties and tracks with no record. Use `release name · provider` only when both values are available, otherwise use the current filename-derived label, including for hand-added `Film.en.srt`. Show one Off option outside the headed language groups. The provider-ID display, group order, Off placement and stable ordering defaults are recorded as `[assumed]`.
5. **Q5 — Selection.** Preserve the existing auto-selection of the newly downloaded track and carry it across the reload by server track ID, including after reordering or relabeling. Use existing attempt/generation guards so a newer viewer selection or explicit Off wins over the in-flight refresh. Preserve the existing absent-track handling.
6. **Q6 — Port and governance.** Add one Core port for the download record, with post-publication write and per-movie batch read. Use one EF adapter under Infrastructure/Persistence and bind it in `PersistenceServiceCollectionExtensions.cs`. The handlers stay in Core and the byte store stays focused on publication. The constitution's closed port list requires an ADR, a MINOR amendment and the allowed-port update in ArchitectureTests. Prepare governance before port implementation and deliver the amendment and architecture-test update atomically with the port. The Conductor allocated ADR 0054 before drafting. Size remains M. This follows the constitution's stated route and requires no structural owner checkbox. No new package, project or layer is required.
7. **Q7 — Path reuse.** Atomically upsert on the unique movie/path key after publication. A new download may reuse a path after external deletion, and its successful write replaces the prior metadata. A missing file is excluded by discovery and its row needs no cleanup sweep. Matching is path-based. Manual replacement at the same path can retain the old metadata until a successful re-download updates it.
8. **Q8 — Dependency and delivery sequence.** Spec work can proceed with DEV-551 at open Spec PR #520. DEV-553 implementation waits for DEV-551 delivery to merge and for pickup to confirm provider ID plus the selected-candidate evidence required for the record. If that evidence is missing, stop at pickup and route `needs recon`. DEV-552 can proceed in parallel. The ordered proof stages are below.
9. **Q9 — Same-key failure limit.** Q2 applies to a failed or ambiguous upsert after reuse. The immediate response uses fallback label and null provenance. A later list can show the prior row if the replacement write did not commit, or the new row if it committed. Discovery still governs file eligibility. Q7 and Q9 are documented path-based and cross-store limits.
10. **Q10 — Closure.** Patron confirmed the frozen scope, all-severity in-scope closing bar, three-axis review, two-round remediation cap and Phase 3 and rebased-head gate sets. The grill is ready for Quill's spec, plan and tasks drafting.
