# DEV-299 Conclusions

## Phase A grill, round 1

1. **Q1 — blocked: structural — May DEV-299 change the stranded-work claim and message contract so the sweeper can enqueue work that a worker can subsequently claim?** Literal claim-then-enqueue livelocks: the sweeper's successful claim makes the worker's required claim return false, so the message is acknowledged without processing. An `Attempt` match cannot safely transfer ownership because the message carries no claim token and duplicate messages could both match. Paging `Pending` through `IMovieCatalog` supplies IDs, not a safe claim handoff. Do not freeze option (a) or (c), and do not invent a repository list method as a silent fix. Basis: DEV-299 Scope item 3; `IMovieRepository.cs:13-17`; `MovieSummary.cs:7`; `EnrichmentRequested.cs:7`; constitution IV:178-188 and Enrichment Reliability:445-452; `specs/PRODUCT.md` §5 ticket-change rule.

2. **Q2 — accept with placement correction.** `RecordEnrichmentFailureCommand(MovieId, int Attempt, EnrichmentFailureCategory)` returns `EnrichmentFailureDecision(EnrichmentFailureAction Action, int? NextAttempt)`: `EnrichmentFailureAction` is a SmartEnum with `Retry`, `RetryDelayed`, and `DeadLetter`. Retry leaves the row Pending and returns `Attempt + 1`; `RateLimited` selects delayed retry. Dead letter calls `MarkFailed(category, timeProvider.GetUtcNow())` and saves. The consumer alone republishes or dead-letters. Put a plain sealed `EnrichmentOptions` record in shared `Core/Pipeline/`, not `Domain/`; the host binds and validates it when wiring this pipeline. Basis: DEV-299 Scope item 3; constitution I:105-119, IV:181-186, VII:246-250, Enrichment Reliability:449-459; `Movie.cs:66-70`; `IEnrichmentQueue.cs:5-8`.

3. **Q3 — accept.** `ApplyEnrichmentResultCommand(MovieId, MetadataLookupResult)` handles `Found` with `MarkEnriched` and `NotFound` with `MarkNotFound`, saves, and rejects `Failed` with `ArgumentException` because failures go to Q2. `ClaimEnrichmentCommandHandler` returns the repository's bool unchanged. Provider lookup and consumer construction of the result belong to their adapter work. Basis: DEV-299 Scope item 3; `MetadataLookupResult.cs:10-20`; `Movie.cs:51-64`; `IMovieRepository.cs:13-17`; constitution Enrichment Reliability:447-451.

4. **Q4 — accept, including the required API mapping.** Missing movie details and a null repository load in an ID-based command throw `NotFoundException`; add the Core/Pipeline type because it is absent. Let `InvalidTransitionException` propagate. Map the new exception to 404 in the existing single API `IExceptionHandler` in this PR; constitution gate 361-362 forces that otherwise unnamed tracked-file edit. Basis: constitution II:138-141, V:201-211, checklist:360-362; `ValidationException.cs:6-16`; `ValidationExceptionHandler.cs:11-35`; DEV-299 Library and command scope.

5. **Q5 — accept.** Results: Import and RequestEnrichment return `MovieId`; Claim returns `bool`; Apply returns `EnrichmentStatus`; RecordFailure returns Q2's decision; Requeue returns the enqueued count; Watchlist Add/Remove and Play return one shared `Unit` sealed record from Core/Pipeline. Basis: `ICommandHandler.cs:6-9`; DEV-299 Scope items 1-5; constitution API Contract Rules:465-467.

6. **Q6 — blocked: structural — May DEV-299 extend the import contract to obtain a unique MovieId before Movie.Create, and specify which port or caller allocates it?** `MovieId.TryCreate` validates an existing positive int; it does not mint one. `Movie.Create` requires the ID before `AddAsync`, while `IMovieRepository` neither allocates nor returns one. The legacy EF movie uses a generated integer ID, so a guessed handler-generated ID is unsafe. Once the contract is settled, use `LibraryPath`, then Scan → Create → Add → Save → Enqueue `EnrichmentRequested(id, 1)`; propagate publish failure for sweeper recovery. Duplicate-path behavior and import-count telemetry are outside the named handler scope; note duplicate detection without creating a ticket until existing tickets are checked. Basis: DEV-299 Scope item 2; `MovieId.cs:6-32`; `Movie.cs:41-49`; `IMovieRepository.cs:7-17`; `src/LamuFlix.Data/Migrations/LamuFlixContextModelSnapshot.cs:76-79`; constitution Enrichment Reliability:454-455 and telemetry:225-230; `specs/PRODUCT.md` §5 ticket-change rule.

7. **Q7 — accept.** The manual retry handler accepts only NotFound or Failed; it rejects Enriched with `InvalidTransitionException` before calling the broader domain method. It then calls `RequestEnrichment`, saves, and enqueues attempt 1. The message attempt restarts while the movie's completed-outcome count remains monotonic. Basis: DEV-299 Scope item 3 explicitly says NotFound/Failed; `Movie.cs:73-77`; `specs/DEV-294/CONCLUSIONS.md:57-59`; `EnrichmentRequested.cs:7`.

8. **Q8 — accept.** Watchlist commands load, use the aggregate's transition, and save; duplicate add or absent remove propagates `InvalidTransitionException`. Playback gets `MovieDetails`, throws `NotFoundException` on null, and calls `IMediaPlayerLauncher.Launch(Path, Format)`. The handler does not launch a process directly; the disabled launcher and registration gate must enforce `Features:LocalPlay` when wired. Basis: DEV-299 Scope items 4-5; `Movie.cs:79-96`; `MovieDetails.cs:7-12`; constitution VII:253-255; `specs/DEV-298/CONCLUSIONS.md` Q7; `specs/PRODUCT.md` §5 care item 5.

Basis: DEV-299 Overview and Scope items 1-6; constitution I:105-119, II:130-141, V:198-211, VIII:261-277, checklist:350-372; `specs/PRODUCT.md` §3.

Deferring AutoFixture/Faker.Net would depart from constitution IX, so add the project references in this ticket. Basis: DEV-299 Scope item 6 and 100% pass AC; constitution IX:286-304 and checklist:370-371; `Directory.Packages.props:31-32`; `tests/LamuFlix.UnitTests/LamuFlix.UnitTests.csproj:10-20`; `specs/PRODUCT.md` §5 care item 1.
