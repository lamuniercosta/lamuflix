# 0020. Request-correlated import enrichment proof

- Status: Proposed - reviewed in Phase A; decision approval depends on Gate 1 spec merge; canonical docs/adr publication occurs in the DEV-318 Phase B delivery PR.
- Date: 2026-10-09
- Ticket: DEV-318

## Context

DEV-318 requires end-to-end proof of HTTP import, RabbitMQ delivery, worker enrichment through OMDb, and one distributed trace. Patron settled that Worker means the existing EnrichmentConsumer hosted in the API, following the established Infrastructure boundary recorded in [0019](0019-infrastructure-consumer-delivery-proof.md) and [ADR-0004](ADR-0004.md). The existing details response has no Status field, and existing trace coverage does not establish the complete chain starting at an HTTP request.

This records a boundary and proof decision, not a production architecture change. Replacing the established host or expanding the public contract would carry meaningful integration and contract-chain costs; preserving that boundary while observing status in Postgres can surprise a reader of the ticket summary. The real trade-off is test-local synchronization and explicit trace ancestry instead of a separate host, public status field, timing delay, or shared-TraceId-only assertion.

Basis: DEV-318 note:10-11; [Patron conclusions](../../specs/DEV-318/CONCLUSIONS.md), Q1-Q4 and Q3 follow-up; [frozen brief](../../specs/DEV-318/brief.md), Q1-Q7; recon-DEV-318:146-182 for the scoped registration seam. [Spec](../../specs/DEV-318/spec.md) and [plan](../../specs/DEV-318/plan.md) express the settled proof; [tasks](../../specs/DEV-318/tasks.md) bind cleanup to the first runnable scenario.

## Decision

Extend `ImportMovieFolder_RealScannerThroughOmdb_PersistsEnrichedMovieWithMeasuredProviderEvidence` additively using the existing WebApplicationFactory, real Postgres and RabbitMQ Testcontainers, active API-host consumer, and WireMock-backed production metadata provider. Preserve every existing import, scanner, details, metadata, measured provider, and owned-folder cleanup assertion. This proves the actual broker crossing and hosted consumer; separate-process isolation is not claimed.

Install a cancellation-aware asynchronous test gate through the existing configureTestServices callback, outside the fully decorated production processing handler and before its claim. Require exactly one descriptor matching ICommandHandler<ProcessEnrichmentCommand, ProcessEnrichmentOutcome>, assert its scoped lifetime and non-null ImplementationFactory, and capture that exact factory. Replace only that descriptor with a scoped wrapper invoking the captured factory with the same scoped IServiceProvider. Preserve Tracing -> Logging -> Validation -> handler and per-delivery AsyncServiceScope ownership. Never resolve the replaced interface recursively, construct the bare handler, copy the decorator chain, create another provider, or retain scoped services in per-test gate state. The gate creates no Activity and must satisfy ValidateScopes and ValidateOnBuild.

Await POST 202 and real consumer arrival at the gate, parse the Location movie id and match it to the delivery MovieId, then read Pending from a fresh Postgres context before release. Release the gate, await persisted Enriched, and assert GET 200 with the unchanged MovieDetailsResponse metadata. Measurement relies on the existing fixture warm-up followed by WireMock Reset: assert exactly one measured OMDb GET filtered by the scenario sentinel apikey and selected t/type values, retaining the existing method/path/query, parameter and secret-scrub assertions. Retry-path behavior remains outside this proof, but a second matching request fails the positive-path count assertion. Do not add another Reset, change the fixture, suppress duplicate matching requests, weaken the count or alter resilience configuration. A fixed response delay or mocked queue, repository, or provider cannot substitute for this proof.

Install disposable, thread-safe AllData ActivityListener capture before host startup. Send unique W3C traceparent and tracestate headers without an ambient test Activity. After request preparation, immediately before sending the POST, assert Activity.Current is null; do not substitute propagation suppression or introduce another Activity. Require the API server span, import ancestry, Enrichment.Enqueue, RabbitMQ.Client.Publisher publish span, Enrichment.Process consumer, processing handler, and Metadata.Lookup to share the request TraceId. Prove import/enqueue ancestry reaches the API server span, publish.ParentSpanId equals enqueue.SpanId, consumer.ParentSpanId equals publish.SpanId, processing handler descends from consumer, and Metadata.Lookup descends from processing handler. Assert propagated tracestate, Consumer kind, and zero links on this first delivery. Correlate by the request trace rather than global span counts; use existing telemetry constants and never steal the delivery with BasicGet.

Use the existing 30-second integration wait budget with cancellation, TimeProvider and existing test-clock seams. Wait boundedly for stopped spans after Enriched, diagnosing the missing span or stuck gate. The scenario-level try/finally owns cleanup on both success and failure exits: its finally releases the gate before host disposal and guarantees capture/listener disposal on either exit. Explicitly verify release-before-host-disposal and capture/listener disposal on both exits, leaving no blocking gate or leaked listener. Retain owned-folder cleanup as part of the first runnable scenario; introduce no new disposal abstraction or separate business failure-path scenario.
