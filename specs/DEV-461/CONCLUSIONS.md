# DEV-461 — Patron Conclusions & Rulings

## Q1: Canonical per-movie Review state (`None` / `Liked` / `Disliked`) independent of `Watched` and `Watchlist`
- **Verdict**: Approved — canonical per-movie `Review` state (`None`, `Liked`, `Disliked`), orthogonal to `Watched` and `Watchlist`, where selecting the active thumb clears to `None` and selecting the opposite thumb switches directly.
- **Basis**:
  - Ticket `DEV-461` (`## Scope`, `recon-DEV-461` lines 148–153): specifies four distinct actions (`Watched`, `Thumbs up`, `Thumbs down` replacing `Not interested`, `Watchlist`), requires `Thumbs up` and `Thumbs down` to be mutually exclusive, and states clicking the active one clears it.
  - Ticket `DEV-461` (`## Open points for the spec`, `recon-DEV-461` lines 166–167): explicitly asks whether `Watched` stays independent of the review (`a watched movie can be liked or disliked`) with `Suggested: yes`, and frames the review domain around `(liked / disliked / none)`.
  - Domain modeling (`specs/PRODUCT.md` §5): modeling a single three-state `Review` value (`None` / `Liked` / `Disliked`) makes mutual exclusion and direct switching an invariant in the type system rather than two independent boolean flags that could contradict each other.

## Q4: Recommendation scoring design, separate liked/disliked `TasteProfile` aggregates, affinity channels (`L` / `D`), and configurable weights (§2.3 items 1, 2, 6 + taste defaults)
- **Verdict**: Approved — preserve the recency-weighted watched/playback baseline while omitting `Disliked` movies from its positive inputs; extend `TasteProfile` with separate liked and disliked aggregates (plot embedding, genres, cast, director, including reviewed-but-unplayed movies, one equal review signal per reviewed movie without review timestamps); compute bounded `[0, 1]` affinities `L` and `D` separately via weighted average of plot cosine (floored at `0`) and metadata weighted-Jaccard channels using existing `SimilarityWeights` (`Genres`, `Cast`, `Director`) plus configurable `ReviewPlotWeight` (default `1.0`, omitting missing/disabled channels and returning `0` when no channel is usable); define profile contribution as `baselineSimilarity + LikedReviewWeight * L - DislikedReviewWeight * D` (defaults `LikedReviewWeight = 1.0`, `DislikedReviewWeight = 1.0`, unclamped so negative review affinity can lower scores) inside existing `BlendProfileWeight`; and enforce startup options validation requiring finite non-negative channel weights, finite strictly positive review coefficients, and at least one enabled review channel.
- **Basis**:
  - Ticket `DEV-461` (`## Recommendations must react to the review` & `## Open points for the spec`, `recon-DEV-461` lines 155–168, 174): requires thumbs-up to raise and thumbs-down to lower the weight of a movie's embedding AND metadata (genres, cast, director) in `TasteProfile` for both For You and Related, and explicitly calls for configurable, validated weights for liked and disliked in `SimilarityWeights` / `RecommendationOptions`.
  - Existing recommendation pipeline & math (`recon-DEV-461` §3 lines 117–126; `recon-DEV-461-2` §2): weighted-Jaccard metadata similarity requires non-negative channel maps (preventing a single signed centroid from representing negative genre/cast/director preferences or avoiding signal cancellation), and `BlendScorer` multiplies the profile term by `BlendProfileWeight`.
  - Structural & taste ruling (`specs/PRODUCT.md` §§4, 5 items 1, 2, 6): fits cleanly inside existing `Features/Recommendations` and `Persistence` types without new dependencies or layers; default numerical weights (`ReviewPlotWeight = 1.0`, `LikedReviewWeight = 1.0`, `DislikedReviewWeight = 1.0`) are logged `[assumed]` in `specs/DEV-461/ASSUMPTIONS.md`.
