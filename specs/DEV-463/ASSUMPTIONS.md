# DEV-463 — Taste & Tie-Break Assumptions

- **[assumed] (Q4/12 — Eligibility filter & key format)**: Eligible trailer candidates require `site="YouTube"` and `type="Trailer"` (case-insensitive) with an 11-character ASCII YouTube video ID matching `^[A-Za-z0-9_-]{11}$`; all other video types (`Teaser`, `Clip`, `Featurette`, etc.), non-YouTube sites, and blank or URL-shaped keys are excluded.
- **[assumed] (Q4/12 — Language vs. official precedence & deterministic tie-break)**: Candidate ranking orders Q3 language tier (`pt-BR` ahead of `original_language`) first, `official=true` ahead of `official=false` within the same language tier second, and `key` ordinal ascending (`StringComparer.Ordinal`) third (deduplicating repeated keys by keeping their best `(languageTier, isOfficial)` rank), without relying on provider array order or `published_at`.
- **[assumed] (Q5/12 — Trailer section copy, iframe title, placement & offline note)**: In `MovieDetailsView`, the Trailer section uses heading `"Trailer"`, iframe `title="Trailer for <movie title>"`, and an always-visible adjacent explanatory note `"Requires internet access. Portuguese captions depend on availability."` inside the existing Movie Details section stack (`details-section`), keeping layout isolated in a responsive 16:9 container without cross-origin load/timeout probes or global CSP middleware changes (required `frame-src https://www.youtube-nocookie.com` is documented in the PR/spec).
- **[assumed] (Q8/12 — Trailer section placement in `MovieDetailsView`)**: The Trailer section is placed in `MovieDetailsView` immediately before `RelatedMovies` (after the primary metadata/cast sections).
