## Phase 4 handler wiring ruling — negative blended relevance in MMR projection (ratified by Patron)

Verdict: Adopt option (a) — in `GetRecommendationsQueryHandler`, when any candidate in the eligible scored pool has `Result.Score < 0.0`, shift `MmrCandidate.Relevance` across the pool by `-min(0.0, minPoolScore)` (so minimum selector relevance is `0.0`) for `MmrSelector.Select` only, while preserving raw `item.Result.Score` on returned `RecommendedMovie` items and keeping `MmrSelector` validation unchanged.

- **Objective difference invariance and DEV-354 penalty fidelity**: Because `lambda * relevance - (1 - lambda) * maxRedundancy` is linear in `relevance`, adding a pool-wide constant offset `-min(0.0, minPoolScore)` adds the same `lambda * offset` to every candidate's objective at every step, preserving exact objective differences, exact `MovieId.Value` ties, and DEV-354 penalty ordering among negative and zero scores (whereas clamping to `0.0` collapses `-0.25` and `-3.0` into ties with `0.0`) (`specs/DEV-416/CONCLUSIONS.md` Q2, `BlendScorer.cs:27-34`, `GetRecommendationsQueryHandlerTests.cs:636-655,696-712`).
- **Selector precondition and nonnegative identity**: When all pool scores are `>= 0.0`, the offset is `0.0` and `MmrCandidate.Relevance` equals `Result.Score` unchanged; when `minPoolScore < 0.0`, rebasing yields finite `Relevance >= 0.0`, satisfying Q3/FR-004 without modifying `MmrSelector.cs` or existing selector tests (`specs/DEV-416/spec.md` FR-002, FR-004, `specs/DEV-416/CONCLUSIONS.md` Q3, Q5).
- **Payload preservation, cross-Take prefix consistency, and Q7 scope**: Computing the offset from the full eligible scored pool before `Take` keeps `Select(pool, a)` a prefix of `Select(pool, b)` for `0 <= a <= b`, while mapping selected IDs back to the unshifted `item.Result.Score` and `item.Result.Reasons` preserves raw finite scores (including `-3.0` and `-0.25`) within the approved Q7 file set (`specs/DEV-416/spec.md` FR-006, FR-008, FR-011, `specs/DEV-416/CONCLUSIONS.md` Q2, Q7, Q11).
