**Accept flattened nullable metadata and validating VO reads; use B for EnrichmentStatus and the existing string Code for EnrichmentFailureCategory.** Metadata scalar columns live on `MovieRecord` in `movies`, with Q1 relationships retained separately. Exact fields and aliases remain Q5. No separate metadata table or native PostgreSQL enum is introduced.

- DEV-19 Scope 2 (`artifacts/DEV-19/receipt.json:4`, description lines 12-15) puts nullable metadata and the Year/ImdbId indexes on the movie configuration. Flattening implements that shape. Carry absent-metadata semantics into the repository follow-up: all-null scalar metadata can represent absence, but nonempty actor/director/genre relationships must not be discarded solely because scalar columns are null. Q5 settles the complete field set; this ruling does not add a presence column or rewrite Core.
- Constitution IV (`.specify/memory/constitution.md:175-177`) already fixes `Pending=0`, `Enriched=1`, `NotFound=2`, `Failed=3` and requires persistence of Value. Store Status as an integer through an explicit Value converter; these identifiers must never be renumbered. Text status A would depart from that decided contract. At this worktree base, `EnrichmentFailureCategory` is a sealed record with a string `Code`, not an int SmartEnum (`src/LamuFlix.Core/Domain/EnrichmentFailureCategory.cs:3-36`): persist its existing codes as nullable varchar(32), restoring the corresponding known singleton and rejecting unrecognised non-null codes. Do not convert either type by its display name, add MapEnum, or change Core to make the two representations uniform.
- Accept converter reads through the same validating domain construction path used elsewhere: use each VO's validating factory, with a converter helper that throws when a TryCreate-style factory returns false; preserve nullable values as null. Invalid non-null data must fail materialisation rather than bypass validation or become null. Basis: DEV-19 Scope 2 VO conversions; constitution Coding Conventions (`.specify/memory/constitution.md:404-414`); existing `MovieId.cs:20-32`, `ImdbId.cs:21-37`, and `ImdbRating.cs:20-33`. No Core factory rewrite is authorised; existing validating constructors remain valid where that is the available domain construction path.
