# DEV-567 — Assumptions

- `[assumed]` **Q1 (Network error toast copy & unavailable diagnostic labels):** On a network error where no HTTP response or problem body exists, show one toast titled `Network error` with explicit unavailable indicators for HTTP status and `traceId` (and omit `reason`), rather than fabricating diagnostic values (`specs/DEV-567/ticket-text.txt:20,30,34`; `specs/PRODUCT.md` §4).
- `[assumed]` **Q4 (Abort/stale suppression & preserving inline error states):** Intentional `AbortController` cancellations or superseded stale responses do not trigger a failure toast; existing inline panel/view error states and `QueryClient` `retry: false` remain unchanged (`specs/DEV-567/ticket-text.txt:13,20,23-25`).
- `[assumed]` **Q5 (Short title fallback & error copy):** Use `ProblemDetails.title` (or a concise generic title such as `Request failed` for HTTP errors without a title, and `Network error` for transport failures) without rendering raw exception messages or `ProblemDetails.detail` (`specs/DEV-567/ticket-text.txt:20,30`; `specs/PRODUCT.md` §4).
- `[assumed]` **Q6 (Toast stack cap, timeout, placement, and `aria-live` defaults):** Mount one app-wide toast host at bottom-end (fitted within narrow viewports), cap visible toasts at 3 (dropping oldest on overflow), auto-dismiss after 5 seconds (paused while hovered or focused), include a keyboard-accessible `Dismiss` button, and announce new toasts once in a persistent `aria-live="polite"` region without moving focus (`specs/DEV-567/ticket-text.txt:17-22`; `specs/PRODUCT.md` §4).
