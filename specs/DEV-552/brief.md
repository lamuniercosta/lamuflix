## Frozen scope

- In the player's CC subtitles tab, start one search per configured preferred language concurrently, across the enabled usable providers via the server fan-out. With an empty preference list, search `defaultLanguage` when present. Keep **Add a language** for other supported languages. Preserve progress as providers settle and report each configured provider, its outcomes and safe reasons, and observed quota where known.
- Group candidates by language with counts. Show provider, release name, match percent, download count and an affirmative hash-match mark. Order groups by configured preference order, then manually added languages in add order. Rank within a language by existing match percent, download count and release-name tie-break. Key selection by opaque candidate ID so incoming results and reordering preserve checked rows.
- **Download selected (n)** snapshots distinct candidate IDs in visual order. Submit every selected row through the current single-candidate route, one at a time. Keep one active batch per media item and show waiting, done, or failure with reason, including **expired, search again**. An expired or failed item leaves subsequent attempts eligible. Use per-provider quota estimates, allow selection above the last observation, and reload tracks once when the batch settles, including batches with failures. DEV-553 owns player track visibility. Preserve accessible checkbox labels and the announced selection count.
- Permit the additive language, candidate and opt-in stream contract changes from Q1, Q2 and Q4 and the Q6 file boundaries. Automatic downloads, deletion, subtitle preview, scorer changes, new hashing work, new dependencies, projects, layers and schema changes are outside scope. Credentials, `Features:LocalPlay` and process-execution boundaries remain outside this change.

Anything else is a follow-up issue, not a finding in this round.

## Approach and contract

1. Build on DEV-551's existing one-language search and stable provider identity. Share the server fan-out between the existing aggregate and the stream representation. Preserve the default JSON response semantics and status codes with the approved additive hash flag. Opt in on the same GET via `Accept: text/event-stream`, using built-in ASP.NET Core 10 SSE. Emit a complete provider outcome and its candidates as each configured provider settles, including immediate off/unusable outcomes. Keep the existing deadlines, safe closed codes and opaque candidate IDs. One explicit terminal event reports the settled provider count. Keep validation/domain errors and no-usable 409 as pre-stream JSON. Cancel outstanding work on disconnect. [ASP.NET Core 10 SSE support](https://learn.microsoft.com/aspnet/core/release-notes/aspnetcore-10.0#minimal-apis)
2. Add ordered, canonical supported `preferredLanguageCodes` on the existing language catalog and a non-null `hashMatch` on the candidate DTO and stream candidates. Carry only affirmative provider evidence through the existing provider result models. OpenSubtitles movie-hash submission is unverified by the supplied recon. Verify the existing signal before claiming a positive mark and document the result in the plan. Use false when there is no affirmative evidence. Any new hashing work requires a separate ruling.
3. Name the C# SSE payload DTOs, including the terminal payload, and verify actual schema emission into `web/src/api/openapi.json` and consumption via generated `web/src/api/types.ts`. Use explicit schema registration if needed. Regenerate both artifacts using the existing workflow. Verify the JSON representation alongside SSE after generation.
4. Keep partial rows after a stream interruption. A stream that ends without terminal completion is incomplete for its language. Offer explicit retry; cancel media-scoped searches and ignore events and batch responses superseded by a media change. Track provider outcomes per language so mixed success and failure remain visible in the one line per configured provider. Show last observed remaining quota or unknown. A download observation supersedes search observations already in flight. Compute selected spend per metered provider without summing remaining balances across providers.
5. Keep the existing per-item download, persistence and provider routing boundaries. If the existing DEV-553 track flow cannot support acceptance, pause for a scoped Patron ruling. No opt-out of the required three-file/three-track or player acceptance is assumed.
