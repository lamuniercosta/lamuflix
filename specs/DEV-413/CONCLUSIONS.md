## Q2 — Write Semantics (`UpsertAsync`, `ComputedAt`, Validation & Concurrency)

**Verdict:** `[from Patron] DEV-413 Q2: ACCEPT — ratify caller-supplied ComputedAt (stored as UTC timestamptz, no repository TimeProvider), null on absent MovieId, single parameterized PostgreSQL INSERT ... ON CONFLICT (movie_id) DO UPDATE replacing vector and computed_at unconditionally (last write wins), pre-SQL guard for null/default/non-384/non-finite vectors (zero vector allowed), FK enforcement for missing MovieId, and CancellationToken propagation.`

- **Atomic upsert & `ComputedAt` ownership (`DEV-413:21`; `recon-DEV-413:19, 26, 78-80`; `constitution.md:278`):** The caller (`DEV-414` consumer) supplies `ComputedAt` on `MovieFeaturesSnapshot` from its own injected `TimeProvider`; `EfMovieFeaturesRepository.UpsertAsync` does not take a `TimeProvider` and executes one parameterized PostgreSQL `INSERT INTO movie_features (movie_id, vector, computed_at) VALUES (...) ON CONFLICT (movie_id) DO UPDATE SET vector = EXCLUDED.vector, computed_at = EXCLUDED.computed_at` statement so repeated or concurrent writes for the same `MovieId` keep exactly one row and atomically replace both `vector` and `computed_at` (last successful DB write wins, no `WHERE` timestamp comparison; `ComputedAt` preserved as UTC instant at PostgreSQL `timestamptz` precision). `GetByMovieIdAsync` returns `null` when no row exists for `movieId`.
- **Pre-SQL validation, zero-vector allowance & DB constraints (`DEV-413:21`; `recon-DEV-413:19, 30, 37, 47, 58, 80`):** Reject `null` snapshot, `Vector.IsDefault`, `Vector.Length != EmbeddingDimensions.Value` (`384`), and any non-finite element (`!float.IsFinite(x)`) before issuing SQL (`ArgumentNullException` / `ArgumentException` in `MovieFeaturesSnapshot` and/or `UpsertAsync`). Permit finite all-zero 384-element vectors in storage (no non-zero constraint in `DEV-413:21`; index creation/existence via `pg_indexes` is the AC (`recon-DEV-413:69`), and cosine ranking semantics belong to `DEV-348`). Non-existent `MovieId` values are rejected by the PostgreSQL `movies` foreign key (`ReferentialAction.Cascade`, matching `PlaybackEventConfiguration.cs:29-32` / `AddPlaybackEvents.cs:27-32`), and `CancellationToken` is checked/propagated on both repository methods (`recon-DEV-413:80`).
- **Recon boundary note:** All storage/write facts above come strictly from `DEV-413:21`, `recon-DEV-413:19-80`, and `constitution.md:136-141`; if exact `LamuFlix.ArchitectureTests` file/line facts are needed for task drafting beyond `constitution.md:141`, request bounded Wisp recon rather than searching inline.
