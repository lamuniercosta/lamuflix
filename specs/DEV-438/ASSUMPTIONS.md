# DEV-438 — Assumptions

- [assumed] Patron Q2: Name tokens are ASCII-alphanumeric runs in the extensionless basename, matched case-insensitively. Every other character is a separator. Only sample, trailer, featurette and extras are excluded. Basis: DEV-438 Proposed scope §1 and primary-video/error-response ACs. This deliberately avoids substring matches and language-specific synonyms.
- [assumed] Patron Q4: failedMovieIds are returned in ascending numeric order for predictable output. Basis: DEV-438 bulk-rescan counts/failed-ID contract; no semantic ordering was prescribed.
- [assumed] Patron Phase 2 Adjudication (7): Concrete identifier names are `PrimaryVideo`, `RescanMovieResult`, `RescanLibraryResult`, `RescanMovieResponse`, and `RescanLibraryResponse` (with `RescanMovieCommand`, `RescanLibraryCommand`, and `internal sealed class RescanMovieOperation` in `Core/Features/Library`), and the `CONTEXT.md` glossary entry for **Rescan** states explicitly that *Rescan* updates the `Format` of an existing `Movie` whereas *Import* creates one. Basis: Constitution Principle VIII (`CONTEXT.md` ubiquitous language), Principle II (sealed command/result records), and DEV-438 Proposed scope §§1–3.
