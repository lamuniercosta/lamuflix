## Summary

Give `LamuFlix.ServiceDefaults` the four capabilities the ticket names and the span-outcome semantics it adds, in one composition root that the Api already calls and no host duplicates.

One `AddServiceDefaults` composes Serilog (console JSON, forwarded to the OpenTelemetry logging provider), OpenTelemetry tracing and metrics with an OTLP exporter on each of the three signals, the health-check registration that already lives there, `TimeProvider.System`, and the options validation that already lives there. One new `MapDefaultEndpoints` extension maps `/health/live` (no checks) and `/health/ready` (only the checks carrying the readiness tag) exactly once, both anonymous. Infrastructure registers the one check it is allowed to know about - the PostgreSQL connection, tagged for readiness - and drops the readiness tag from the metadata-provider check while leaving it registered. `TracingDecorator` learns the ticket's two-valued span outcome: a `ValidationException` leaves the span status unset and records a validation-failed handler outcome; every other exception sets the error status and records the exception's full type name. Everything is asserted: the composed providers and the resolved OTLP endpoint through the service provider, the readiness membership on the **real** registrations read from a built provider, both probe routes through `WebApplicationFactory<Program>` with the checks replaced by stubs — so `Api/Program.cs`'s own composition is executed, not read, at the cost of the one project-file change N2's first half puts to the owner (§8) — and both span paths against an installed `ActivityListener`.

**Nothing in this plan pre-empts an open owner question.** The package set and its pins (Q1) and the health body contract with the Degraded mapping (Q2) stay open; every task that depends on one is marked and blocked on it, and the four items that cannot be settled at all today (N1 to N4, §8) are carried as needs decisions rather than quietly met or dropped.

## 10. Test Strategy

Three projects, nine test files (7 new, 2 edited), no container and no collector anywhere.

**`tests/LamuFlix.UnitTests/Pipeline/TracingDecoratorTests.cs`** (new) — the two AC4 paths, each under an `ActivityListener` installed the way the existing `tests/LamuFlix.Test/TracingDecoratorTests.cs:101-112` already installs one: a validation failure leaves `Status == ActivityStatusCode.Unset` with `TelemetryConstants.HandlerOutcome` set to `TelemetryConstants.HandlerOutcomeValidationFailed`; any other exception sets `Status == ActivityStatusCode.Error` with `ErrorType` equal to the exception type's **full** name. Both assert the rethrow. **A change that made the two behave identically fails the suite** (FR-024, SC-010) — that is the property the ticket's Decision is for. `constitution.md:302-303` prefers `Theory` + `MemberData` over repeated `Fact`s, and every other multi-case shape in this plan takes that preference; **these two cases are the one exception, and the reason is the property itself**: a theory whose two rows run the same assertions through the same helper would still pass if a change made the two paths behave identically, because a mutant that breaks one row of two fails only that row's test, not the other. Two separate `[Fact]`s are what make SC-010's "0 changes can make the two identical without failing the suite" arithmetic true. The exception is recorded here and in the task text, not taken quietly.

**`tests/LamuFlix.UnitTests/ServiceDefaultsTests.cs`** (new) — the US1 and US2 evidence against a bare `WebApplicationBuilder`:
- the tracer provider, the meter provider and the log provider all resolve from the built provider, and each carries its OTLP exporter (SC-003, FR-027);
- `IOptions<OtlpExporterOptions>` resolves and reports host `localhost`, port `4317` and `Protocol == OtlpExportProtocol.Grpc` by default, and the `OTEL_EXPORTER_OTLP_ENDPOINT` value when that variable is set. **These two do not share a class**: the default case and the one-endpoint case stay here because neither touches process state, and the set case moves to **its own file and class inside a `[CollectionDefinition(..., DisableParallelization = true)]` collection**, copied from the shape `MetadataProviderProbe.cs:17-21` already uses. The reason is that the variable is **process-wide**: while it is set, any other class xUnit runs alongside observes the override, and same-class ordering stops none of that. The `finally` restore stays regardless, and neither the collection nor the restore may be dropped on the strength of the other;
- one `[Theory]` with three `[MemberData]` rows — AspNetCore, HttpClient, Npgsql — proving each instrumentation actually **reaches the built provider**, with a capturing `BaseProcessor<Activity>` attached through `ConfigureOpenTelemetryTracerProvider` (no new package: both types ship with what T019 brings). The AspNetCore row makes a real in-process request to a self-hosted endpoint — no container, no broker, no `TestServer` package; the HttpClient and Npgsql rows start an activity on the instrumentation's own source and operation name, copied verbatim from recon R2 (recon round 9).
