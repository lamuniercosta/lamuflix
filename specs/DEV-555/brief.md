## Plan-challenge decisions (r1)

Keel's plan decisions from the step 6 adjudication. Each one cites the finding it closes (see [CONCLUSIONS § Plan challenge r1](CONCLUSIONS.md#plan-challenge-r1-adjudication-phase-2-step-6-keel)). They sit inside Q1–Q5 and override the draft wherever the two differ.

- **D1 Attempt budget (Sentry H1, L2).** At the start of each session-open attempt, compute `share = (remaining − W) / untried`. `W` is the 8 s wait if T003 proves it is required and 0 otherwise. If `remaining ≤ W`, stop trying and report `failed`. An attempt is the session open only. Once a session opens there is no failover: the wait (if any), the search and the close run on that server within the overall remaining deadline. A search failure or timeout after open produces `failed` with “BSPlayer is not answering”. Close gets no reserved budget. It runs only if time remains and never fails returned results. Tests: (i) ≥3 servers, where server 1 hangs, server 2 refuses and server 3 answers; assert server 3 is reached and results return inside the deadline. (ii) Close has zero remaining budget: close is skipped and results return as success.
- **D2 Session scope (Sentry H2).** The session token is a local in each search call, never a field. The adapter is stateless apart from injected services. Close is awaited within the remaining budget, and its exceptions are logged scrubbed and swallowed. Test: two concurrent searches on the recorded fake, which returns a distinct token per open; assert that each search and close carries its own token.
- **D3 Destination gate (Sentry H3 a–d).** One shared refusal gate, which extends the existing host-refusal service rather than reimplementing it, is applied to every SOAP request and every download URL before contact. A URL is allowed only if all of these hold: it is absolute; its scheme is `https`, or `http` when `AllowPlainHttp` is true; it has no userinfo; its host is not an IP literal; its host, normalized with `Uri.IdnHost`, compared case-insensitively and with one trailing dot stripped, exactly equals the host of a `Servers` entry or a `DownloadAllowedHosts` entry (no suffix or wildcard match); and its effective port equals that entry's effective port. Relative and protocol-relative URLs are refused. Any 3xx counts as a failed attempt and is never followed. DNS-rebinding pinning is out of scope (Q2; recon line 66). Table tests assert zero contact for: a relative URL, a protocol-relative URL, an IP literal, a trailing-dot or case variant (allowed when it matches, refused when it does not), a disallowed port, userinfo, and `http` with `AllowPlainHttp=false`.
- **D4 Cancellation (Sentry M1).** Create the provider deadline source with `TimeProvider`, and create each attempt source linked to it and to the caller token. On `OperationCanceledException`: if the caller token fired, propagate cancellation as the DEV-551 contract specifies (cited at T001) and never map it to `failed`. If the provider deadline fired, report `failed` with “BSPlayer is not answering”. If only the attempt fired, move to the next server. Test: caller cancellation during a probe produces a cancellation outcome, not `failed` and not the timeout text.
- **D5 XML (Sentry M2, Ledger L2).** Build requests with `XElement`/`XmlWriter`, never string concatenation. Read each response through a counting stream capped at `MaxResponseBytes`, and abort the attempt as soon as the cap is exceeded, before parsing (check `Content-Length` first when present). Never truncate and parse. Parse with `XmlReader`: `DtdProcessing.Prohibit`, `XmlResolver = null`, `MaxCharactersFromEntities = 0`, `MaxCharactersInDocument` derived from the configured bound. Malformed XML or a bad encoding fails the attempt. Tests: an over-bound body is aborted before parsing; a DOCTYPE with an internal-entity expansion payload is refused.
- **D6 Hash divergence (Sentry M3).** If T003 proves a difference, add a separately named, functionally named routine in `MovieHash.cs`. The BSPlayer adapter calls it, and the existing routine stays byte-identical. The existing OpenSubtitles hash tests stay unchanged and green. Add an OpenSubtitles golden-value test only if none exists (cite at T001).
- **D7 Inconclusive capture (Sentry M4).** If the T002 capture for the generated file returns no candidates or no download link, the operator makes a second capture: a search for a home-library movie that BSPlayer knows, using the hash and size LamuFlix computes on the home cluster. Commit only the scrubbed SOAP bodies and that hash and size, never media bytes. Download-host shape and hash acceptance (a non-empty match for the LamuFlix-computed hash) come from that capture. If it also yields no download link, STOP blocked for a ruling. No allowlist is assumed (Q2).
- **D8 Deterministic time (Sentry M5, Ledger M3).** The deadline is `new CancellationTokenSource(timeout, timeProvider)`, and waits are `Task.Delay(delay, timeProvider, token)`. `HttpClient.Timeout` stays infinite, per the existing registration (recon line 14). Timing tests (D1, D2, D4, all-servers-down) run the real adapter over a stub `HttpMessageHandler`. A hanging server is simulated by a task that never completes until its token is cancelled. The test owns `FakeTimeProvider.Advance`, and there are no wall-clock assertions. The WireMock recorded fake covers the wire shape only: the contract suite, the hash, and the XML and refusal behaviour.
- **D9 Telemetry and logs (Sentry L1, Ledger L4).** Reuse the existing and DEV-551 provider spans, metrics and attribute keys (cited at T001), and add no new attribute keys. Server host and attempt number may appear in structured logs, never as telemetry tags. Logs carry the movie id, the attempt number and the failure category (Principle VI), and never the session token. Test: captured logs contain no token and do contain the movie id.
- **D10 Fixtures (Sentry L1).** The known file for the hash proof is generated in the test from deterministic bytes, and no media or binary file is committed. The committed fixtures are only the scrubbed SOAP bodies and mappings under the DEV-549 layout.
- **D11 Options shape (Ledger M1).** No new options record. BSPlayer binds a named instance of the existing `SubtitleProviderOptions`, as DEV-551 lands it, from `Subtitles:BsPlayer`. Binding happens at the existing subtitle-provider registration site cited at T001, without `ValidateOnStart`. It reuses `RequestTimeout`, `DownloadAllowedHosts` and `MaxDownloadBytes`, and DEV-551's `Enabled` and `AllowPlainHttp`. It adds only `Servers` (`string[]` of absolute URLs) and `MaxResponseBytes` (`long`); both stay inert for the OpenSubtitles instance. The BSPlayer adapter ignores `ApiKey`, `BaseUrl`, `UserAgent` and `DownloadLinkHost`. Validation of the `Subtitles:OpenSubtitles` instance stays byte-identical, and the existing validator tests stay unchanged. The download cap follows the precedence the OpenSubtitles adapter already applies against the global `Subtitles:MaxSubtitleDownloadBytes` (cited at T001) and never exceeds that global cap. If DEV-551's landed shape makes a named instance impossible, STOP for a ruling.
- **D12 Identifiers (Ledger M2).** Adapter `BsPlayerSubtitleProvider`, which the VIII adapter-class rule allows. The section key `"Subtitles:BsPlayer"` is a const on that adapter class and doubles as the options name, which the vendor-mandated-key rule allows. Options record: `SubtitleProviderOptions` (existing). Validator: extend the existing `SubtitleProviderOptionsValidator` (functional name). Typed client: `AddHttpClient<BsPlayerSubtitleProvider>`, keyed by the adapter type. Health registration name and telemetry names: functional, following the DEV-551 per-provider mechanism. Outcome reason text: “BSPlayer is not answering”, the ticket's own text (Wanted 4). Tests: `BsPlayerSubtitleProvider*Tests` and the DEV-549 fixture folder, named for the adapter under test. If the DEV-551 provider identifier requires a new vendor-named `TelemetryConstants` entry, that is a VIII departure: STOP and route it as `blocked: structural` (PRODUCT §5 b). Do not add the entry.
- **D13 Home enablement (Ledger M4).** Home settings are untracked under Principle VII (`docker/api.settings.json` or the `api-settings` Secret). T004 edits no home file. The tracked `docker/api.settings.example.json` (T011, if T001 confirms it is a setup-doc surface) carries the full `Subtitles:BsPlayer` block, documented as plain HTTP. T017 lists the exact keys the operator sets in the home settings before the live search.
- **D14 Static state (Ledger L1).** New or changed production code has no `static readonly` and no mutable static state. That covers SOAP templates, `XmlReaderSettings` and any session cache. Use `const`, locals or instance members instead.
- **D15 Validator rules (Ledger L3).** When `Enabled=false`, nothing is validated, no calls are made, and health reports disabled. When `Enabled=true`, the provider is unusable (zero calls, host keeps running) if `Servers` is empty, or any entry is not absolute, has a scheme other than http or https, uses `http` while `AllowPlainHttp=false`, has an IP-literal host or carries userinfo, or `RequestTimeout ≤ 0`, `MaxResponseBytes ≤ 0` or `MaxDownloadBytes ≤ 0`, or any `DownloadAllowedHosts` entry is blank or contains `*`. An empty `DownloadAllowedHosts` is valid: downloads are then limited to `Servers` hosts by D3. `https` entries are valid when `AllowPlainHttp=true`. Tests use Theory + MemberData (Principle IX).
