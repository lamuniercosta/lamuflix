## Round 4 item 2 clarification of Q2 and Q3

The Q2 no-usable-provider **search** 409 is determined during request-time acquisition configuration validation. Fix provider usability at that point for the request. Subsequent timeout, quota, failure, or lack of formable search input settles the provider outcome and leaves that usability decision intact.

Classified `off` and `unusable` (startup-refused) rows are settled outcomes under Q3 as soon as classification completes. A provider can settle before upstream I/O. The Q2 search 409 always includes the additive ProblemDetails `providers` array with the classified rows in configured order, using the same `providerId`, `state`, safe `reason`, and nullable `quota` shape as the search response. Quota is null when unobserved. Existing request-level validation or domain errors that take precedence before or instead of provider settlement omit the `providers` key entirely. A legacy search error with settled provider outcomes carries the same extension. Preserve legacy HTTP statuses and existing ProblemDetails fields.

T010 must assert the ordered classified rows on the Q2 409 and the absence of the key on the request-level error branch. Carry this distinction into FR-003, FR-004, the search-response contract, and CHK027.

Basis is Q2 and Constitution Principle VII for the configuration-time 409, Q3 and DEV-551 Wanted 5 and 10 for classified rows and the additive error extension, Q5 for provider-local request-time outcomes, and DEV-551 task note lines 33 and 35 for the clarification request.
