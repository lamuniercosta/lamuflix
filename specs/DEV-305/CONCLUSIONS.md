# DEV-305 Conclusions

## Sentry M1 — LocalPlay / Process.Start (§2.3 item 5)

**Ruling:** Accept the OS-association fallback in DEV-305 as legacy parity, with M1 recorded as an accepted Medium risk; no launcher fix in this ticket and no owner checkbox. Require a separate hardening ticket to land before the play endpoint is wired; Rigger must check existing tickets before filing.

- **Scope and authority:** DEV-305's verified ticket text requires player resolution from `PlaybackOptions.Players`, `ArgumentList`, disabled-mode exception, and flag-based registration; it specifies no unmapped-format policy (Maestri note `DEV-305:15`). Patron decides this local-execution care item (`specs/PRODUCT.md:34-47`); this ruling changes neither the ticket nor the constitution.
- **Launch semantics and parity:** Constitution VII (`.specify/memory/constitution.md:253-255`) requires gated playback and argument-safe launches. I interpret its shell prohibition as command-shell invocation or composed shell commands: [Microsoft Learn, UseShellExecute remarks](https://learn.microsoft.com/dotnet/api/system.diagnostics.processstartinfo.useshellexecute?view=net-10.0#remarks) distinguishes graphical-shell document opening from command shells. The configured-player branch uses `ArgumentList`; the fallback supplies only `FileName`, with no command string (`src/LamuFlix.Infrastructure/Playback/ProcessMediaPlayerLauncher.cs:20-32`). DEV-280 explicitly preserved the legacy `UseShellExecute`/`FileName`/`ArgumentList` assertions (`specs/DEV-280/spec.md:86-89`), including the unmapped-player case (`tests/LamuFlix.Test/UnitTest1.cs:104-109`).
- **Residual risk and sequencing:** Argument safety does not make arbitrary OS associations safe: executable, script, and shortcut files may run code. LocalPlay defaults off and no endpoint invokes the launcher yet (verified by Sentry, Maestri note `findings-DEV-305-Sentry:8-12`, and Keel's ask). Follow-up: fail closed when no player is configured, or permit OS opening only for an explicit media-extension allowlist checked against the actual file path; retain the flag and argument-safety requirements. Its merge is a prerequisite for wiring the play endpoint, not a DEV-305 code change or a claim that M1 is fixed.
