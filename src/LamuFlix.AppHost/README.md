# LamuFlix AppHost

Local-only .NET Aspire orchestration for LamuFlix development. One command starts disposable Postgres, RabbitMQ, the Api, the Vite dev server on `http://localhost:5173`, and the Aspire dashboard.

This AppHost is a separate local entrypoint from Docker Compose. It does not change, replace, or depend on `docker-compose.yml`.

## Prerequisites

| Requirement | Details |
|---|---|
| .NET SDK | `10.0.401` with `rollForward: latestPatch` per [`global.json`](../../global.json) |
| OCI container runtime | Docker Desktop or Podman, running. Aspire starts the Postgres and RabbitMQ containers itself. |
| Node.js | `>=24 <25` on `PATH`, per `web/package.json` `engines`. The AppHost launches `node` directly. |
| Web dependencies | Run `npm install` in `web/` once (and after dependency changes). The AppHost runs `node_modules/vite/bin/vite.js` and never installs packages. |
| Private Api secrets | `Library:RootPath` and `Omdb:ApiKey` in the Api user-secrets store (see below). |

## Private Api user secrets

The library path and the OMDb key are yours, not the AppHost's. The AppHost never reads, copies, or commits them: it sets `DOTNET_ENVIRONMENT` and `ASPNETCORE_ENVIRONMENT` to `Development` on the Api resource, so the Api loads its own unchanged user-secrets store.

```bash
dotnet user-secrets set "Library:RootPath" "<absolute path to your movie library>" --project src/LamuFlix.Api
dotnet user-secrets set "Omdb:ApiKey" "<your OMDb API key>" --project src/LamuFlix.Api
```

Keep live values out of the repository and out of the AppHost project. Missing or invalid values fail Api startup clearly; no validation or health check is bypassed to obtain a green dashboard. Postgres and RabbitMQ credentials are generated by Aspire and persisted to the AppHost's own user-secrets store (the `UserSecretsId` in `LamuFlix.AppHost.csproj`), which is separate from the Api store.

## Run

From the repository root:

```bash
cd web && npm install && cd ..
dotnet run --project src/LamuFlix.AppHost
```

Or press F5 on the AppHost project to use the `https` launch profile in `Properties/launchSettings.json`, which starts the AppHost with the Aspire dashboard enabled.

The dashboard URL is printed in the console. The web SPA is always at `http://localhost:5173`; the Api listens on a dynamic localhost port assigned by the AppHost.

Startup ordering is enforced by health, not by process start:

1. Postgres and the `lamuflix` database report Healthy, and RabbitMQ reports Healthy, before the Api starts.
2. The Api answers `/health/ready` before Vite starts.
3. Vite answers HTTP `/` on 5173.

## Values the AppHost supplies

These are non-secret local-development values. Production and Compose configuration are unchanged.

| Setting | Value |
|---|---|
| `Enrichment__ClaimLease` | `00:00:30` |
| `Enrichment__SweepInterval` | `00:00:10` |
| `RabbitMq__RetryDelay` | `00:01:00` (longer than the claim lease) |
| `Database__ApplyMigrationsOnStartup` | `true`, for the AppHost-launched Api only |
| `VITE_API_BASE_URL` | The Api `http` endpoint the AppHost assigns |

`RabbitMq__HostName`, `RabbitMq__Port`, `RabbitMq__UserName`, and `RabbitMq__Password` are mapped from the AppHost RabbitMQ resource and its generated credentials; they are never hardcoded. No worker and no Ollama resource is started.

## Disposable local data

Postgres and RabbitMQ run without named volumes. Their contents are disposable and disappear when their containers are recreated, and a fresh database applies the existing EF Core migrations on first start. Keep anything you want to keep outside this stack.

Container ports are mapped dynamically on localhost with no management UI. Port 5173 is the one fixed port: Vite runs with `--strictPort` and Aspire endpoint proxying is disabled, so an occupied 5173 fails the startup instead of silently moving the SPA.

## AppHost versus Docker Compose

| | AppHost (this project) | Docker Compose |
|---|---|---|
| Command | `dotnet run --project src/LamuFlix.AppHost` | `docker compose up -d --build` |
| Purpose | local development with dashboard, F5, and Vite hot reload | the full container stack, including Ollama for embeddings |
| Resources | postgres, rabbitmq, api, web (Vite on 5173), dashboard | postgres, rabbitmq, api (with its in-process workers), web (nginx on 3000), ollama, ollama-model-init |
| Configuration | AppHost-generated container credentials plus your Api user secrets | `.env` and `docker/api.settings.json` |
| Data | disposable, no named volumes | `ollama-models` named volume |

The two entrypoints share no state and are started independently. Use one at a time. `docker-compose.yml`, `docker-compose.observability.yml`, and the Docker settings files are unchanged by this project.
