# Store portable movie-folder identities relative to the library root

DEV-459 stores and returns a canonical library-relative LibraryPath instead of deployment-specific absolute folders, preserving movie IDs and enforcing case-insensitive uniqueness across Windows and Docker. Paths preserve segment casing, use `/`, and represent the root as `.`; runtime reads resolve under the configured Library:RootPath, allowing the library mount to move without changing stored identities.

The API host and its hosted Worker consumers await a configuration-aware, exclusively locked, transactional startup backfill that validates every row and rejects unknown roots, conflicting mappings and exact/case-only collisions without partial updates. Library:LegacyRootPaths and the unambiguous standard `/media/library` alias map historical Windows/UNC/POSIX paths independently of host OS; new imports accept only relative paths or absolutes beneath the active root, and database enforcement preserves portable uniqueness under concurrent imports while retaining the existing exact unique index.

Keep the existing ThumbnailRequested message shape. Canonicalize old absolute payloads through the same map, compare the canonical folder to the current movie for that ID, then apply existing authorization under the active root. Legacy aliases remain until queued deliveries, retries and DLQ replays are exhausted. Never infer historical roots from a basename, authorize messages on ID alone, or resolve relative media paths against process CWD.

The trade-off is coordinated stop-then-upgrade downtime and fail-closed startup instead of partial or heuristic migration. All API host instances require matching configuration; after successful backfill a downgrade restores a pre-upgrade database backup with matching old binaries. No reverse backfill, new dependencies, queue schema, API shape or LocalPlay/launcher changes are introduced. Basis: DEV-459 ticket scope and Patron A1–A7 in specs/DEV-459/CONCLUSIONS.md; this proposed ADR awaits the specification/Gate 1 process.

Patron A8 selects a .NET whole-string ToUpperInvariant derived movies.library_path_key with binary deterministic unique IX_movies_library_path_key, retaining IX_movies_library_path. All supported writers update path and key together; PostgreSQL enforces uniqueness, while key derivation is a trusted-writer responsibility. Shipping-runtime Unicode equivalence checks against OrdinalIgnoreCase are mandatory and a mismatch returns to Patron. Startup validates key consistency and fails closed on drift. The awaited gate in src/LamuFlix.Api/Program.cs after Build and before Run covers HTTP and hosted consumers; preflight precedes atomic locked backfill, key population and constraint activation, with fresh/legacy schema and rollback/restart proofs. Existing business columns and duplicate outcomes remain unchanged. Basis: CONCLUSIONS.md A8 and recon-DEV-459-2 section 9. Status remains proposed.

Patron A9 fixes derivation at the Infrastructure LamuFlixDbContext: sync and async SaveChanges share one private pass over added/modified MovieRecord entries, setting the whole-string uppercase key. Core, converters and individual repository writers do not derive it. Backfill also writes path and key together. MovieLibraryPathMigrationGate is a sealed concrete Infrastructure Persistence class with no interface or Core port. LibraryOptionsValidator validates legacy roots through existing options registration; validated options resolve before the transaction opens. Core canonicalization uses pure strings; filesystem resolution stays in Infrastructure.

Startup order is additive Migrate when enabled, then the awaited gate, then Run. The gate takes LOCK TABLE movies IN ACCESS EXCLUSIVE MODE as the first statement in one DbContext transaction, then performs whole-table preflight, backfill, key population, column-collation change, non-null/unique activation and consistency verification atomically. No concurrent index build. The final model uses property-level UseCollation("C"); gate DDL explicitly sets library_path_key column collation C before the final schema assertion. When ApplyMigrationsOnStartup is false the gate only verifies the final activated state and fails closed with schema-not-ready if it is absent; it performs no migration or activation. A Migrate-only database is not a supported serving state.

Patron A10 sanctions the two-scaffold tooling composition proved in recon-DEV-459-3 section 10. Scaffold AddLibraryPathKey from an interim nullable/no-index source model into Persistence/Migrations. Change source to final required key, property collation C and unique index; scaffold LibraryPathKeyActivation to an absolute TEMP directory outside the worktree. Tooling rewrites the existing in-repo model snapshot to final; only the additive migration ships. The external activation migration/designer are disposable scratch, never shipped, archived or hand-edited. No generated artifact inside the worktree is hand-edited, suppressed or manually deleted. Require a clean pending-model-changes check, PG17 Migrate applying only additive schema, and an unrelated later scaffold with no activation operations.

This composition accepts a maintenance cost: removing the immediate successor of AddLibraryPathKey restores its interim designer snapshot. Before applying further migrations, repeat the final-model external scaffold, verify has-pending-model-changes exits 0, and inspect the next scaffold to ensure it does not re-emit activation. Operations/migration docs must retain this recovery procedure; warning suppression cannot substitute for it. Supported write paths, final column collation, lock/atomicity, fresh/legacy/flag-off startup and post-gate schema alignment require the planned real-database evidence.

All Api instances sharing a catalog require matching application/runtime versions, globalization mode, ICU/Unicode data and root/alias configuration. Coordinated shutdown, compatibility checks and backup are hard prerequisites; startup drift checking is a backstop. No additional pre-activation interlock is introduced. Any shipping-runtime Unicode-equivalence counterexample stops dependent work and returns through recon to Patron for decision and artifact revision; no gate is waived. Basis: CONCLUSIONS.md A9-A10 and recon-DEV-459-3 section 10.
