# ADR-0001. Ports and adapters with a feature-organised core

- Status: Accepted
- Date: 2026-09-24
- Ticket: DEV-292 (parent DEV-281)

## Context

The solution is one bounded context, Movies. Vertical-slice architecture and four-layer Clean Architecture were the alternatives on the table.

## Decision

Use ports and adapters with a feature-organised core.

This is not vertical-slice architecture: slices do not own their own data access. This is not four-layer Clean Architecture: there is no separate Domain assembly. The application core is organised by feature. The seams are the file system, the metadata provider, the message queue, and the media player process. Each seam is a port in Core with an adapter in Infrastructure.

One aggregate with eight use cases is the right size for feature folders. The four seams are the boundaries that are slow, non-deterministic, or machine-specific, so testability, substitutability, and resilience sit on those ports without extra assemblies.

## Consequences

- The README describes the style as "ports and adapters, feature-organised core, explicit handlers with decorators", not as VSA or Clean Architecture.
- Adding a port requires an ADR.
