# ADR-0012. pgvector with local Ollama embeddings vs hosted vector APIs

- Status: Accepted
- Date: 2026-10-17
- Ticket: DEV-350

## Context

Recommendations need similarity search over movie plot embeddings. Embeddings must be stored and queried alongside the existing movie data, work on a developer machine without network access, and stay deterministic under test.

## Decision

- Store plot embeddings in pgvector in the same PostgreSQL instance that holds movie data. No separate vector database process.
- Generate embeddings with a local Ollama container. No hosted embedding API on any code path.
- Tests use a deterministic fake embedding generator. No test calls Ollama or any hosted API.

## Consequences

- No ongoing external API cost and no external rate limits on ingest or query.
- Fully functional offline: Postgres with pgvector and the Ollama container are the only runtime dependencies.
- Deterministic testing with the fake generator: embedding values are seeded and repeatable, so similarity assertions do not depend on model output.

## Rejected alternatives

- Pinecone: hosted-only vector database. Rejected because it adds a network dependency, an ongoing cost, and a second data store beside Postgres.
- Qdrant Cloud: hosted vector database. Rejected for the same reasons as Pinecone: network dependency, ongoing cost, and a second data store beside Postgres.
- OpenAI embeddings API: hosted embedding API. Rejected because it requires network access, incurs per-call cost, is subject to rate limits, and makes test output non-deterministic.

## Sequencing

This ADR is accepted before DEV-345 and DEV-346 start, because both implement this decision. It no longer depends on DEV-348.
