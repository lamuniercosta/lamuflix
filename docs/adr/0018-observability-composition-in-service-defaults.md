## Decision

- Compose traces, metrics and logs in the existing idempotent `AddServiceDefaults`, preserving clock registration, options validation and Serilog console logging. Tracing includes ASP.NET Core, HttpClient and Npgsql instrumentation, and the application, `RabbitMQ.Client.Publisher` and `RabbitMQ.Client.Subscriber` sources named by `TelemetryConstants`. Metrics include ASP.NET Core, HttpClient and the existing application meter identity; logging reaches OTLP alongside the console pipeline. Each exporter uses argument-free `AddOtlpExporter()`, retaining standard environment configuration and endpoint precedence. Reuse installed dependencies; add no resource identity, endpoint override, project, layer or schema.
- Commit HttpClient instrumentation together with the OMDb sentinel redaction proof. Default URI redaction is the protection: the query is replaced by `*` and user-info and fragment are removed by default, so no production logging change, no suppression, no client-category level filter and no extended-logging package is added, and the metadata-provider registration keeps health membership as its only planned edit. The preventive action is the proof itself: the probe propagates the logger category, captures Debug and above and records scope state with active scope payloads attached, so the `HTTP {HttpMethod} {Uri}` scope that carries the URI is visible to the check. The real metadata lookup must produce at least one stopped client span, the application lookup activity and HttpClient-category log entries, and at least one of those records must carry a structured `Uri` containing the stub host and path and neither the API key nor the sentinel, before the sentinel and its escaped form are shown absent from every span tag, event, status description, log category, rendered message, structured key and value, scope payload and exception text. Preserve URI redaction; use no credential literal. If the sentinel is present, that finding returns to the owner and is never met by an opt-out, a suppression or a weaker assertion.
- Centralize `HealthCheckTags.Ready = "ready"` beside `TelemetryConstants` in Core/Pipeline. Infrastructure registers the PostgreSQL check over the existing `LamuFlixDbContext`; PostgreSQL and RabbitMQ are the two ready-tagged registrations. The metadata-provider check remains registered and untagged. Prove membership from real registrations independently of endpoint stubs. Reconcile the existing liveness route and host-test harness through receipts.
- In `TracingDecorator`, expected `ValidationException` leaves span status Unset and records `lamuflix.handler.outcome=validation_failed`; unexpected exceptions set Error and `error.type` to the full exception type name. Both paths rethrow unchanged. Keep constants centralized and prove both paths with an `ActivityListener` in the active UnitTests project; the retained legacy assertion is not executing proof.
- `/health/ready`, its writer and endpoint tests remain **BLOCKED on owner Q2/OD-1**. No provisional body or default writer is authorized. The owner must answer the complete inherited question, including the FR-034 contract-chain deferral clause; an explicit owner deferral is recorded as such and does not authorize implementation. Readiness is not counted as delivered or deferred while the answer is absent.

## Consequences

The existing architectural boundaries and installed packages remain sufficient. Provider/exporter composition is proved separately from collector delivery, and only on the production-composed host: no test-local recomposition, no new public API, csproj or `InternalsVisibleTo`. Exporter attachment is shown behaviourally by flushing each provider against a stub receiver; the six named sources are shown reaching a recording processor through a passive test listener that never samples above `None`, sitting beside the production listener that alone creates and records; endpoint options are read from the container the production composition built and keep environment precedence; and each of the three named instrumentation registrations has an executed removal receipt showing that removing it fails only its own check. Process-environment tests are isolated in a non-parallel collection and restore their changes.

Production log eligibility follows Serilog's own filtering and configuration, because the OTLP logging pipeline is fed through the existing provider bridge; the console pipeline and the OTLP path coexist without either suppressing the other. Debug-and-above capture in the redaction test is a test requirement, not a promise that production emits every Debug record, and a local positive log reaching the composed provider is evidence that the seam is not vacuous rather than proof of network export.

With no collector reachable, telemetry is dropped: the exporters fail to the OpenTelemetry SDK and OTLP exporter EventSources only, never to `ILogger` or Serilog, so the application keeps running and application errors stay visible. An operator can opt into exporter diagnostics with `OTEL_DIAGNOSTICS.json`; no diagnostics file is committed and none is produced by tests. Exporter configuration stays argument-free, so no timeout, protocol, endpoint or processor argument is set, and shutdown spends at most the documented 10 s per-exporter budget. Tests flush with an explicit timeout, never sleep for a batch delay, and dispose every host and provider they build. If a process-wide provider changes what an existing capture test observes, the fix is narrower correlation inside that test; global telemetry is never disabled and no test is skipped.

Health membership can be completed independently of the blocked readiness contract.
