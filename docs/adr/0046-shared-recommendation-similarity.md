# Use one similarity score across recommendations

DEV-518 gives Related ranking, For You MMR redundancy, and collection block ranking one ordered scorer and one evidence breakdown. The scorer evaluates Collection, Director, Themes, Plot, Cast, and Genre. Each contribution divides the weighted criterion value by the sum of all six configured weights (15 at defaults). Missing inputs contribute zero. Positive matches produce reasons in table order, with display thresholds for Themes, Plot, and Genre. See the [normative table](../../specs/DEV-518/spec.md) and [validation and test requirements](../../specs/DEV-518/plan.md).

The scorer retires release year, runtime, IMDb rating, writers, the “Identical feature profile” reason, and the separate SimilarStoryThreshold path. Plot supplies “Similar story” through the ordered scorer. Startup validation requires a finite positive sum of the six weights, finite positive ThemesCeiling, finite ordered Plot bounds in the cosine domain, display thresholds in [0,1], and MinimumKeywordMovies of at least 1. Explicit scorer calls reject invalid scoring inputs. Present-terms normalization was rejected because dropping absent signals from the denominator inflated the remaining matches.

## Consequences

- Themes computes rarity-weighted cosine against one population. The catalog reads library N and distinct n_k from one PostgreSQL statement or a transaction with repeatable-read or stronger semantics, so 0 ≤ n_k ≤ N even during writes. An empty library yields zero Themes.
- Related and For You each resolve one immutable keyword snapshot at their operation boundary and pass it explicitly into all scorer pairs, including Related collection grouping and For You MMR. The scorer stays pure. Mid-operation invalidation preserves that operation’s snapshot, and the next operation refreshes. This trades immediate refresh within a request for consistent ranking across its comparisons.
- The singleton cache serves one shared catalog in one API process and loads through a scoped calculator. Successful commits invalidate it alongside the genre weights cache and at keyword-membership mutations that refresh counts even without genre invalidation. Cover all production commits that change the counted population. Failed writes preserve the snapshot. A version token rejects stale in-flight repopulation, cancellation aborts stale-version retries, and failed loads propagate without being cached.
- Cache lifetime depends on complete commit-site coverage from T001. A TTL would allow stale counts after known writes, and per-pair reads would repeat database work and could mix populations across a ranking operation. The existing catalog and cache boundaries support the design. Per-population keying and distributed invalidation remain outside the approved single-catalog, single-process deployment.
