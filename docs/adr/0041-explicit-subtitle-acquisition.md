# Explicit subtitle acquisition with guarded Subs publication

DEV-501 replaces automatic prepare acquisition with free language search and a viewer-selected download, using the existing provider seam with OpenSubtitles as the only implementation. The server owns candidate identity, paths and quota mapping; public DTOs remain provider-neutral so another provider can be added without changing the UI or routes. This follows ticket owner rulings 5–7, reproduced in `recon-DEV-501:33–63`, Patron Q1–Q9 and approved plan-challenge catalog/D1–D5 rulings in `specs/DEV-501/CONCLUSIONS.md`, whose operative decisions are recorded in `specs/DEV-501/brief.md`.

Candidates are bounded, expiring process-local bindings to movie/language/provider metadata; restart or expiry requires a new free search. This avoids a database/schema or dependency for transient selections at the cost of explicitly stale results. Downloads publish validated SRT atomically and without replacement inside the server-derived movie Subs directory, trying `<stem>-<code>.srt`, then `<stem>-<code>(N).srt`. Containment is enforced in code even on a writable library mount. Leading-dot `.srt` staging stays undiscoverable through explicit discovery exclusion and tests (Q9); cleanup touches only owned staging, never existing or published library files (Patron Q7 supersedes Q5's direct-write mechanics).

Read-only libraries retain search and local subtitle playback while download is visibly disabled. Quota exhaustion, timeout and acquisition configuration failures preserve video and local tracks; only provider-supplied quota/reset values are displayed. There is no automatic paid download or automatic retry. DTOs flow through OpenAPI to generated TypeScript.

Retire prepare-only route/flow/config/tests while retaining shared client, moviehash, typed options, secret isolation and safe atomic IO. Patron Q2 rules the corresponding prepare-specific Principle VII replacement is ticket-mandated maintenance; the spec/plan must include its amendment/version procedure and preserve acquisition-vs-local-serving protections. This ADR proposed that alignment; it is now Accepted by constitution amendment 1.16.0 (`.specify/memory/constitution.md` Sync Impact Report, 2026-11-12). Accepting this ADR does not itself grant Gate 1, implementation compliance or runtime acceptance. Runtime acceptance remains open until the home-cluster receipts, real browser playback and BS Player recognition required by the ticket are recorded.

## Language catalog and concrete Core collaborators

`GET /api/subtitles/languages` returns 200 `SubtitleLanguagesResponse` with nullable `defaultLanguage` and ordered bilingual `languages` entries (`SubtitleLanguageOptionDto`: code, englishName, nativeName), private no-store, without a provider key or call. `SupportedSubtitleLanguages` is the single Core catalog used for query/preference validation; trim and match codes with OrdinalIgnoreCase, emit canonical codes only. Deduplicated configured preferences come first in configured order, then remaining entries by ordinal English name/code; empty preferences are valid and yield null default with no automatic search. Explicit supported-language search works with otherwise valid provider settings.

Use concrete `SubtitleMatchScorer` and process-local singleton `SubtitleCandidateBinder` in Core Features/Subtitles, without a new port/layer. Binder uses injected TimeProvider and seeded Random under lock to issue opaque 32-hex-character tokens; no cryptographic-security claim is made. Existing typed SubtitlesOptions carries CandidateTokenTtl (five minutes, positive) and CandidateStoreMaxEntries (1000, at least one). Purge expired entries (`expiresAtUtc <= now`), then evict earliest expiry with FIFO ties when full. Cross-movie, expired, evicted or process-lost bindings give 400 stale_candidate before paid calls. No shared replica state or affinity implementation is added; an unavailable binding requires free re-search. UI serialization is not a cross-request idempotency or content-deduplication guarantee.

## Provider observations, errors and resource bounds

POST performs movie/binding/read-only/config/containment prechecks before any paid call; read-only wins over provider-config failure. Unknown/positive observed quota permits the explicit call after prechecks; known exhaustion returns 429 download_quota_exhausted. GET with invalid provider settings returns 409 provider_not_configured; valid settings on a read-only library still allow free search with read_only_library download availability. Errors use RFC 7807 ProblemDetails with approved `reason` and optional known `quota` extensions; the contract document enumerates the reason/status mapping. GET 429 is search_rate_limited, never evidence of exhausted download quota. Provider-relative reset durations convert with `timeProvider.GetUtcNow().Add(duration)`; unknown values stay null, elapsed reset alone never replenishes quota, and no failed-call charge/refund is asserted without metadata.

Typed MaxSubtitleDownloadBytes defaults to 2 MiB and is enforced during provider-body read before buffering/staging; invalid/oversized SRT fails with 502 provider_unavailable. Typed MaxSubtitlePublicationAttempts defaults to 10,000, counting the unsuffixed slot first. Reuse one leading-dot staging file across collision attempts; check containment before create, after create/before stage, and before every non-replacing publication. Attempt exhaustion returns 409 read_only_library, with only owned staging cleaned in finally. Bounds are positive validated configuration, not gate-threshold changes. Propagate request cancellation across search/read/stage/publish; caller cancellation is not 504, which is reserved for an upstream timeout while the caller remains active.
