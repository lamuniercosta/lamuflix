# ADR-0009. Typed movie query and sort

- Status: Accepted
- Date: 2026-09-29
- Ticket: DEV-297

## Context

Movie browse filtered and sorted through reflection (`DynamicQuery<T>` and `DynamicSort<T>`). Unknown sort names threw, and nullable titles sorted nulls first when ascending. The canonical browse handler still belongs to later tickets, while the live MVC path has to keep working.

## Decision

- `MovieQuery` is a sealed Core record. `MovieSort` and `SortDirection` are closed SmartEnum values: Title, Year, Rating, Runtime; Ascending, Descending.
- `MovieQueryValidator` in Infrastructure accepts page size 1–100, page number >= 1, ordered ranges when both bounds exist, and a present sort and direction. Empty ranges are valid.
- `MovieQueryString` formats and parses with the BCL. Array keys repeat, enumeration values use Name, and equality compares genre, actor, and status sequences in order.
- `EnrichmentStatus` is `SmartEnum<EnrichmentStatus, int>` with Pending = 0, Enriched = 1, NotFound = 2, Failed = 3.
- Nullable legacy titles sort NULLS LAST in both directions.
- `DynamicQuery<T>` and `DynamicSort<T>` are removed.

## Consequences

- The typed query is covered by FsCheck round-trip and validator properties. The MVC path no longer fails with 500 on an unknown sort; it falls back to Id descending.

## Compatibility and retirement

DEV-298 and DEV-299 retire the temporary Web predicates and `LegacyMovieSort`. Until then the MVC path keeps `QueryParams` and `MoviesFilterViewModel` and does not use the canonical validation decorator. EF translation is evidenced on PostgreSQL 16.4 only. MySQL translation on Pomelo 8.0.31 is unproven.
