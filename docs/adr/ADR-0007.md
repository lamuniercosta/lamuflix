# ADR-0007. Runtime OpenAPI contract with Development-only Scalar and fail-closed drift proof

- Status: Accepted
- Date: 2026-10-08
- Ticket: DEV-312 (parent DEV-284)

## Context

DEV-312 requires first-party OpenAPI generation, Scalar at `/scalar`, a committed `web/src/api/openapi.json`, a Verify drift test in `LamuFlix.IntegrationTests`, and this ADR. The existing Minimal API DTOs and TypedResults metadata define the business contract. Consumers need a reviewed document, and the existing CI Test step must reject silent contract drift.

The decisions are recorded in [brief.md](../../specs/DEV-312/brief.md) Q1–Q5 and [CONCLUSIONS.md](../../specs/DEV-312/CONCLUSIONS.md). The constitution mandates Microsoft.AspNetCore.OpenApi, Scalar, and Verify. The owner-approved OD-1 health-contract deferral remains with DEV-20 then DEV-320.

## Decision

Pin `Microsoft.AspNetCore.OpenApi` 10.0.12, `Scalar.AspNetCore` 2.0.15, and `Verify.XunitV3` 30.3.0 through Central Package Management. The Phase B package ruling in [CONCLUSIONS.md](../../specs/DEV-312/CONCLUSIONS.md) supersedes the original OpenAPI 10.0.0 pin after its vulnerable transitive dependency blocked restore; no direct `Microsoft.OpenApi` pin is added. The same ruling approves disabling MVC application-part assembly attributes and removing the OpenAPI XML-comment source generator to preserve the no-MVC-reference composition. Generate at runtime through the Development test host; do not add `Microsoft.Extensions.ApiDescription.Server`, a generator project, a script, or a CI step.

Register document `v1` using the .NET 10 OpenAPI 3.1 default with no version override. Include exactly the nine existing `/api` path/method operations from current DTO and TypedResults metadata. Health routes and their metadata remain unchanged. Map GET `/openapi/v1.json` and Scalar `/scalar` only in Development; both documentation routes return 404 in Production. This adds an explicit Development branch in `Program.cs` without changing business routes, DTOs, statuses, handlers, or LocalPlay wiring.

The generated `web/src/api/openapi.json` is the sole authoritative baseline and is never hand-edited. Compare the complete document in normal tests and CI, including paths, operations, parameters, schemas, status codes, and info title/version. Normalize CRLF to LF on each compared text only, with no scrubbers. Before Verify runs, assert same-run complete three-way equality between the generated document, the committed contract, and `tests/LamuFlix.IntegrationTests/Snapshots/OpenApiContractTests.DriftMatchesCommittedBaseline.verified.json`. The Verify snapshot is derived and never consumed as the contract; a missing contract or snapshot fails the drift test. Resolve both files independently of the process working directory through the stable `Directory.Packages.props` repository-root marker, failing closed on a missing or ambiguous marker. No auto-accept or tracked-file writes occur in normal tests or CI, and received files stay untracked.

Intentional regeneration is an explicitly enabled local path in the IntegrationTests project, skipped unless `LAMUFLIX_REGENERATE_OPENAPI=true`, selected with `FullyQualifiedName~OpenApiRegeneration`. It uses the same Development host, default client base URI `http://localhost/`, document path, and repository-root marker as the drift test and writes identical normalized bytes to the authoritative document and derived snapshot together for human review in one commit. [quickstart.md](../../specs/DEV-312/quickstart.md) records the command. CI never enables regeneration; its existing Test step generates and compares the document, failing on drift.

## Consequences

- Developers can inspect the contract through Scalar in Development; the committed document remains available to consumers in every environment.
- Integration proof covers exact operation membership and DTO/status metadata, documentation absence in Production, complete equality and Verify, repeated-generation determinism, and controlled drift failure without baseline writes.
- Tests use the existing ApiHostFactory without persistence or messaging operations, keep Features:LocalPlay false, and never execute the play route. Existing composition tests remain unchanged.
- Intentional contract changes require a reviewed `openapi.json` diff and matching derived snapshot. TypeScript/client generation remains subsequent contract-chain work; this ticket introduces no handwritten consumer types.
